# 开发指南

扩展和开发预览共用 `extension/` 中的源码。页面直接加载 HTML、CSS 和 JavaScript，无需编译。

## 开发与预览

在功能分支修改源码，用预览检查布局和模拟交互，确认后由 GitHub Desktop 检查、提交并合并到 `main`。分支保存尚未定稿的改动；`dev/` 只提供预览入口和模拟接口。

在项目根目录运行：

```sh
python -m http.server 8000 --bind 127.0.0.1
```

- [快捷窗口](http://127.0.0.1:8000/dev/preview.html)：切换单视频、系列课程、字幕语言、无字幕和保存状态
- [工作台](http://127.0.0.1:8000/dev/workbench-preview.html)：切换课程、连接和导入场景
- [直接预览整理笔记](http://127.0.0.1:8000/dev/workbench-preview.html?state=series&page=notes)

修改后点击“刷新预览”。预览读取当前分支的正式页面，并模拟扩展消息、存储和素材；不会向 Obsidian 写入内容。技能目录同步、剪贴板和下载仍使用浏览器本身的能力。

真实扩展测试时，在 Edge 加载 `extension/`，源码改动后重新加载扩展，并重新打开页面。

## 修改界面文字

固定标题和说明直接修改对应 HTML；随状态变化的按钮、提示、计数和输入占位文字集中在 `extension/shared/ui-text.js`，按页面分组。比如 `importButton.savedCount` 的 `已导入 {count} 个课时` 可以改成自己的写法，保留键名和 `{count}`，数量仍由页面自动填入。保存后刷新预览即可查看。

笔记模块默认写法、整理方法和生成的任务内容仍在 `notes/rules/` 和 `notes/generator.js` 中维护。接口返回的错误原文由接口提供。

## 工作台的职责边界

`workbench/app.js` 挂载四个页面片段，再创建各控制器，将消息发送、导航、提示和所需接口显式传入。各模块使用工厂函数持有自己的状态。

- `shell.js` 只负责切换页面；`feedback.js` 只负责轻提示
- `catalog/page.js` 管理课程、选中课时、章节、字幕读取和普通导入队列。其他页面通过 `getState()` 读取当前课程，通过 `request()` 发送课程请求
- `connection/page.js` 管理连接配置；`transcription/page.js` 管理组件连接与转写队列，借用课程目录的状态和公共操作
- `notes/page.js` 管理表单和生成文件预览；`materials.js` 获取本次实际素材；`generator.js` 根据输入生成文本，不读取 DOM 或访问接口；`delivery.js` 执行下载、写目录与复制

页面结构分别放在各功能目录的 `page.html`，通用外观放在共用 CSS，功能样式跟随功能目录。不要将页面业务重新放回入口脚本。

## 后台与共享代码

`background/index.js` 是扩展后台入口，按依赖顺序加载服务。浏览器页面通过 `chrome.runtime.sendMessage` 调用后台。

| 文件 | 职责 |
|---|---|
| `settings.js` | 读取、验证、测试和保存连接设置 |
| `bilibili.js` | B站元数据、字幕轨道与字幕读取；分发平台字幕请求 |
| `youtube.js` | YouTube 页面、播放列表和转写文稿读取 |
| `obsidian.js` | 本地 REST 请求、已有原始素材查找 |
| `courses.js` | 课程消息入口，组织读取、导入和课程清单更新 |
| `transcription.js` | 本地转写组件消息和任务处理 |
| `quick-import.js` | 快捷窗口后台导入和状态存储 |

`shared/course.js` 保持为纯课程工具，供 popup、工作台、后台和测试复用。字体、图标及许可也只保留一份。

## 整理规则只有一个来源

通用方法与用户配置分开维护：`rules/workflow.md` 保留完整整理流程，`rules/tasks.md` 定义各任务的做法，`rules/mermaid.md` 维护按需读取的绘图规则，`rules/defaults.js` 提供可编辑的模块和属性默认值。

生成器将通用规则和当前用户配置组装为八个文件：

- `SKILL.md` 与 `agents/openai.yaml`
- `references/workflow.md` 与 `references/tasks.md`
- `references/mermaid.md`
- `references/preferences.md`、`references/modules.md`、`references/properties.md`

源码中的 `rules/` 是生成输入，生成后的 `course-notes/` 才是完整可安装技能。Mermaid 规则随技能交付，不再维护独立绘图技能包。

本地 agent 使用已安装技能和实际素材路径；网页 AI 使用导出的正文与规则。二者共用整理规则，各自生成适合其能力的任务指令。

## 验证和发布

```sh
node --test tests/*.test.cjs
```

测试覆盖课程分组、字幕读取、后台消息、导入、任务生成、文件交付和页面初始化。界面改动再用对应预览场景检查；真实 Obsidian 连接、扩展环境、目录同步和本地转写另做实际流程测试。

`scripts/build_install_package.py` 构建发布安装包；`asr/` 管理本地转写服务和安装向导。仅在准备发布时运行构建，开发重构无需更新安装包或版本号。

本地转写安装程序由 `asr/installer.iss` 定义，运行环境安装逻辑位于 `asr/setup-runtime.ps1`。构建需要 Inno Setup 6.5+：运行 `python scripts/build_asr_installer.py`，或通过 `--iscc` / `INNO_SETUP_COMPILER` 指定 `ISCC.exe`。构建输出 `downloads/vid2notes-asr-setup.exe`，同时复制到扩展中的下载入口。
