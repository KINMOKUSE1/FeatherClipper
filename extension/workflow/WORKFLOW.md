# 课程笔记整理规则

本文件与同目录的 `NOTE_TEMPLATE.md` 用于指导 AI 整理已导入的课程字幕。课程导入清单和所选原始字幕是本次素材；`PROMPTS.md` 仅提供可选的任务提示词示例。

## 规则顺序

本次用户明确要求优先；其次采用下表中用户修改后的偏好，再参考同目录的笔记模板；其余整理方法是默认规则。偏好与模板示例栏目不一致时，以修改后的偏好为准。使用 `course-notes` 技能时，本文件及个人模板优先于技能内置默认值。

## 我的偏好（默认值，可直接修改右列）

| 项目 | 默认值／可修改内容 |
|---|---|
| 学习目标 | 理解课程、完成练习与复习 |
| 输出目录 | `Note/课程笔记/<课程名>/` |
| 笔记作者 | 留空；提供署名时写入成品，留空则省略 `author` 字段 |
| 整理范围 | 按最终确认的分组每组一篇；英文课程以 Lecture 为基本单元，同一 Lecture 的分段合并；普通数字章节保留完整两级编号；指定 P 或文件时仅处理指定素材 |
| 文件命名 | 章节分组：`课程缩写-完整章节编号-主题.md`，如 `CO-2.2-整数运算.md`、`CO-2.3-浮点数.md`、`CS61C-02-数值表示.md`（Lecture 02）；单 P 成篇时：`课程缩写-P序号-主题.md` |
| 笔记语言 | 简体中文；专业术语首次出现保留英文原名 |
| 自测题 | 按知识点覆盖需要生成，附答案并标明为生成练习 |
| 外部资料 | 允许补充解释并注明来源；联网可用时检索字幕提到但未完整收录的真题 |

## 整理方法

### 确认覆盖范围

读取课程清单与实际文件，以清单确认章节归属。记录可用素材、未导入、无字幕和文件缺失；以实际分 P 清单核对数量。保留标题中的“拓展”“例题”“大纲已删”等标注。单文件任务可直接从文件开始。

按上表的整理范围划分成品。英文课程默认以 Lecture 为基本单元：`Lecture 02.1`、`02.2`、`02.3`、`02.4` 自动归入 `2`，合成一篇 Lecture 02 笔记；同一 Lecture 的多个 Part 及同号 LIVE 也归为一组，不同 Lecture 分别成篇。分段内容按知识点放在笔记内部的小标题中，不逐视频拆篇。普通数字章节仍以完整两级编号区分：`2.2` 的多个 P 合成一篇，`2.3` 另成一篇，不合并为第 `2` 章。自动识别依赖标题中的 `Lecture`／`Lec` 标记，不凭英文语言或平台猜测讲次；旧清单仍按分段编号时先在工作台“重新识别章节”，核对后更新清单。本次任务指令列出了分组时采用该分组，否则采用课程导入清单；原始字幕中的旧章号和标题推断不覆盖已确认的分组。只选中一组的部分 P 时注明实际覆盖范围，不自行补入未选素材。`0` 表示未分章，不是共同章节；按用户指定范围整理，未明确如何合并时先确认。用户明确调整整理粒度时采用其要求。

### 把讲解变成知识结构

在每个成品分组内，按知识点组织概念、定义、适用条件、公式、推导和易混淆点。合并重复讲解，保留不同实例。单组内容较长时可分批整理，再统一术语并合成该组笔记。

教师例题放在对应知识点附近，按“条件与数据 → 过程 → 结论与理由”展开。保留具体参数、代码、算法输入、中间状态、拓扑、权值和表格条目。教师强调的原话可用引用块；补充示例与改写解释单独标明。

### 保留回看的入口

- 成品笔记以连贯阅读为主。在“详细笔记”的每个主要内容板块标题（如“一、从机器人抓取理解学习信号”）旁，通常放一个指向该段起点的视频链接，如 `[回看 P1 00:34](视频时间链接)`。总结、术语表、自测题等综合栏目不机械配链接。
- 后半讲回扣前文、跨视频补充或独立例题不在上述入口附近时，可在对应子标题旁补充必要的少量回看链接。按实际讲解位置安排，不强求每个标题都标，也不把多个不连续来源硬塞进一个入口。
- 普通正文、简短举例与引文共用所属标题的回看入口，不逐句插时间戳，也不再另起“来源：时间范围”行重复标注。只使用素材中可确认的视频与时间。
- 字幕缺少的板书、图表、公式或题干列为“需回看视频”，写清位置和缺失内容；优先指向已有标题或回看入口，确有不同定位需要时再补链接。重要术语、数值和符号有歧义时列为待核实。
- 以上只约束视频回看链接的密度。论文、网页、书籍等非视频来源仍在相关论述处按需引用；课程视频总链接保留在笔记属性或来源区。

课程内容、整理者解释和外部资料分别标注。补入真题时核对年份、科目、题号、题干及答案出处，附可靠链接；尚未找到原题时保留已有线索。来源有冲突时说明差异。

### 形成可复习的笔记

按本文件的偏好和 `NOTE_TEMPLATE.md` 整理。默认包含要点、术语表、详细笔记、自测题与答案、来源和“我的补充”；用户调整偏好后，不强行补回删去的栏目。图表放在对应小节：比较用表格，流程与结构用 Mermaid，真实时长和并行关系用比例时间线。

## 保存与继续学习

- 交付前核对小节覆盖、例题数据与推导、术语、来源、公式和图表。已有批注与人工修改保留；后续补充合并到对应小节，难以合并时另存修订稿。
- `draft` 表示整理中，`partial` 表示本次范围仍有影响完整性的缺失，`complete` 表示已核对完成。单 P 的状态对应这个 P。
- 在课程目录的 `整理进度.md` 记录范围、成品路径、已用 CID／文件、缺失项和状态。单文件任务也可直接在成品中记录。
- 原始字幕留在采集目录，课程导入清单由插件维护。需要归档时整体移动课程目录并更新引用，补抓前检查归档位置。
- 成品使用实际来源、日期和标签；多词标签用连字符。表格内 LaTeX 的竖线用 `\mid`、`\lvert` 和 `\rvert` 表达，普通竖线须转义。
- 交付时说明成品位置、处理范围和待核实项；聊天工具可直接输出供保存的 Markdown。

## Obsidian 格式

- 中文内容不使用 ASCII 框线图；对比关系用 Markdown 表格，流程和结构按需用 Mermaid。
- Mermaid 的中文或含特殊字符的节点、边标签使用英文双引号；子图使用简短 ID 和显示标题，图形生成后检查语法与关系。
- 加粗文字紧贴后续汉字而渲染异常时，在两者之间留空格；内联代码中不要嵌套三反引号代码围栏。
