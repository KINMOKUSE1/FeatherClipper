# Mermaid 图解

在课程内容需要流程、结构、状态或消息交互图时读取本文。用户本次要求和个人写作偏好优先；图形能改善理解时再绘制，文字或表格足够清楚时直接采用

## 选型与来源

读取目标段落及其来源，列出图要表达的节点、关系、条件和数据。选择能清楚表达关系的最简单图形；复杂关系拆成总览和局部图，多个主题分别绘制

| 类型 | 指令 | 适合内容 |
|---|---|---|
| 流程图 | `flowchart TD` 或 `flowchart LR` | 流程、分支、结构与处理链路 |
| 时序图 | `sequenceDiagram` | 协议消息、API 调用与参与者交互 |
| 状态图 | `stateDiagram-v2` | 生命周期、状态及转换条件 |
| 类图 | `classDiagram` | 对象、类型、方法与关系 |
| 实体关系图 | `erDiagram` | 数据实体、键与关系 |
| 甘特图 | `gantt` | 有明确日期的项目安排 |
| 思维导图 | `mindmap` | 简洁的概念层级 |
| 时间线 | `timeline` | 按先后顺序排列的事件 |
| Git 图 | `gitGraph` | 分支与合并历史 |
| 饼图 | `pie` | 类别较少的占比 |
| 桑基图 | `sankey-beta` | 各阶段之间的定量流动 |
| 块图 | `block-beta` | 高层组件布局 |
| 象限图 | `quadrantChart` | 两个维度的定位与比较 |

重复映射与概念对比优先使用 Markdown 表格。需要表达精确时长、重叠区间或协议占用时间时，列出起止值、单位和时长；不把普通 `timeline` 的视觉间距解释为时间比例。采用当前预览环境支持的图表类型

图放在对应知识点附近，保留来源中的数值、方向、分支和标签。补充示意单独标明；缺失的拓扑、参数、板书与关系注明待核实，不凭字幕猜出原图

## 写法与布局

- 节点使用唯一的字母、数字或下划线 ID；中文放在显示文本中，例如 `step1["收到 ACK"]`
- 子图使用短 ID 和显示标题，例如 `subgraph phase1["拥塞避免"]`
- 复杂节点文本和边标签用英文双引号包围；显示文本中的双引号可写为 `#quot;`
- 流程图按内容选择上下或左右方向；决策节点使用 `{}`，起止节点使用 `([])`
- 节点首字符避免 Markdown 编号 `1.`，可用 `①`；解释性长句放在图外，节点标签保持简短
- 时序图按消息含义选择箭头，在标签中写清请求、返回或事件；状态图标明转换条件
- 颜色与分组用于区分实际类别，同一含义保持一致；不依靠颜色单独表达关系
- 在 Markdown 中使用 `mermaid` 代码围栏；用户要求更新笔记时保留周围正文和人工批注

## 核对与交付

检查节点 ID、括号、引号、子图闭合、箭头和代码围栏，再对照来源检查关系方向、分支条件、数值与单位

有可用渲染环境时预览图表，检查文字遮挡、阅读顺序和图幅，必要时拆图或缩短标签。只有源码检查时说明未完成渲染检查，不把它当作显示效果验证

本地 agent 按本次授权把图放入对应笔记；网页 AI 输出包含 Mermaid 代码块的完整 Markdown，由用户保存。用户只要图时提供图表和必要的简短说明
